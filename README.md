# 达人筛选 Skill v2.0-draft（内容匹配 × 价格效率 双核心）

定位：巨量星图人工初筛后的 Excel 二次精筛，输出人工建联优先名单（P1 优先建联 / P2 推荐建联 / P3 观察候选 / 议价候选 / 待复核）。

> 状态：候选规则（基于 77 条真实星图数据第一轮分析），阈值未冻结；v1.0 逻辑保留在 `config_v1.yaml.bak` 与 git 历史（tag/分支）中。

## V2 关键变化

1. 取消「互动率 3% 一票否决」→ 低于 1.5% 转为质量复核信号（真实数据：知识类内容互动率中位 2.02%，旧门槛误排率过高）
2. CPM 分档（≤15 高效 / 15–20 良好 / 20–30 可谈 / >30 低效）进入双维矩阵；植入口径 = 植入视频报价 ÷ 预期播放量 × 1000，预期播放缺失时回退星图「预期CPM」文本的 20-60s 档（已验证 = 植入报价口径）
3. 人工内容标签文件（按星图 ID）：无「已核验」的二级内容证据时**不得输出 P1**，最多 P2 并标记「内容细分待核验」
4. 确定性修复：外部总分与等级来源一致；门槛字段缺失不静默通过（转待复核）；风险标签分级（排除/复核/提示）；星图 ID 保留 + 去重 + 导出
5. 每次运行存档：评分版本 + 输入文件 SHA256 + 分级快照（JSON）

## v1.0（旧版）

## 用法（3 条命令）

```bash
# 1. 装依赖

# 2. 筛选（终端直接打印 Top10，Excel 输出 3 个 sheet）
python kol_filter.py --input 达人数据.xlsx --output 推荐清单.xlsx
```

输入支持 `.xlsx / .xls / .csv`（CSV 自动尝试 utf-8-sig / utf-8 / gbk / gb18030）。77 人表格约 1 秒跑完。

## 输出

终端：按排名打印 Top N（排名 / 昵称 / 梯队 / 等级 / 互动率 / 女性占比 / 均播 / 报价 / CPM / 五维分 / 复核标记），并列出所有「建议人工复核」的人及原因。

Excel 三个 sheet：

| sheet | 内容 |
|---|---|
| 推荐清单 | 全部通过硬门槛的达人，含完整字段、复核标记与复核原因、推荐理由 |
| 排除清单 | 未通过的达人 + 具体排除原因（数值化，如「互动率低（2.14% ≤ 3%）」） |
| 筛选统计 | 原始人数、通过/排除人数、三梯队人数、复核人数、本次生效的阈值与配置版本 |

## 三条核心规则

**1. 梯队由五维分等级决定，加分项只在梯队内排序**

```
S / A  → 第一梯队-强烈推荐
B      → 第二梯队-推荐
C      → 第三梯队-可考虑
```

排序键：`梯队 → 加分项 → 五维总分 → 互动率`。C 级达人即使加分项很高，也不会排到 B 级之前。
（旧版按加分项总分定梯队，出现过「五维 48.7 分/C 级」排在第一梯队的情况，本版已修正。）

**2. 异常复核标记（只标记，不排除、不降权）**

命中任一条打「建议人工复核」：

| 信号 | 含义 |
|---|---|
| 互动率 > 10% 且完播率 < 5% | 高互动低完播，可能是引导型互动或异常值 |
| 粉丝增长率 < 0 | 正在掉粉 |
| 近 30 日视频数缺失或为 0 | 更新停滞或数据缺失 |
| 互动率 > 批内中位数 5 倍 | 显著离群 |
| 关键指标（互动率）单元格缺失 | 该列存在但这一行是空的，门槛无法核验 |

两点补充说明：

- 若「近 30 日视频数」整列空缺率超过 `视频数缺失比例上限`（默认 50%），说明数据源根本不提供该字段，此时只打印一次全局提示、不再逐行标记，避免把有效信号淹没；明确为 `0` 的行始终标记。
- 单元格缺失走「标记不排除」而不是「判为不通过」——这是筛选历史复盘里确认要修的老问题（旧版把 `nan` 当成不达标排除）。

**3. 阈值全部在 config.yaml**

`kol_filter.py` 里没有任何业务阈值，硬门槛、避雷词表、加分项、梯队映射、复核信号、五维打分权重与等级切点全部来自 `config.yaml`，每条都标了来源（v2 = 2026-09-15 已验证标准；星图 = 主项目星图模式口径）。

## 五维分怎么来的

输入里若有 `等级` / `五维总分` 列就直接用；没有就由本 skill 内置打分器计算，口径移植自主项目「星图模式」：

| 维度 | 权重 | 计算依据 |
|---|---|---|
| 账号健康度 | 15% | 粉丝量分段 + 近 30 日视频数分段（缺失时用预期播放量代理） |
| 内容质量分 | 25% | 星图指数 + 完播率（≥30% 满分）+ 种草指数 |
| 知乎调性匹配分 | 25% | 垂类知识性（知识友好赛道 70 分 + 二级知识词最多 +10）+ 高知画像（资深中产+新锐白领 ≥50% 满分） |
| 互动质量分 | 20% | 互动率（≥8% 满分）+ 完播率 |
| 数据真实度分 | 15% | 互动率合理区间 + 粉丝增长率 + 粉丝/均播刷量检测 |

等级切点：S ≥ 78 / A ≥ 65 / B ≥ 50 / C < 50（星图模式独立阈值）。缺失子项跳过并重新归一化权重，不会因为缺一列就把分数拉到 0。

## 字段自适应

脚本按 `config.yaml` 的 `字段别名` 匹配列，缺列只会打印提示并跳过对应规则，不会报错：

```
[筛选] ⚠ 缺「标题」列，相关规则跳过（候选列名：视频标题/标题/代表作标题1/代表作标题2）
```

常见影响：缺 `风险标签` → 跳过风险门槛；缺 `互动率` → 跳过互动率门槛与互动维；缺 `报价/预期播放量` → 跳过 CPM 规则；缺 `标题` → 标题加分记 0、避雷词只查昵称与赛道。

同一字段有多个候选列同时存在时（例如同时有 `植入视频报价` 和 `视频报价`），取非空值最多的那一列。

## 已知限制

- 五维分为绝对分档（不做批内归一化），因此等级可能与主项目数据库里的历史结果略有差异；同一份配置对同一批数据的输出是稳定的。
- 批内互动率中位数用于复核信号，会随输入批次变化；如需固定基准，可在配置里替换为常数（当前实现需改 `review_flags` 的入参）。
- 只做筛人/排序/导出，不做采集、看板、状态管理、投放效果回填。
